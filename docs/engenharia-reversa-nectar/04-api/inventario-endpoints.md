# Inventário de endpoints — API pública `nectarcrm-api`

Fonte raiz do repositório: `https://github.com/ColmeiaSolucoes/nectarcrm-api` (lido em rodada anterior).
Todas as entradas abaixo são **CONFIRMADO POR API** (fonte: arquivo `README.md`/`schema.json` de cada pasta `docs/<entidade>/` no GitHub), exceto onde marcado como INFERIDO ou NÃO VERIFICADO.

Nota geral: a maioria das pastas documenta a API como permitindo "controle total" (CRUD) da entidade, mas o `README.md` de cada pasta frequentemente só exibe o endpoint de listagem com exemplo. Onde o método HTTP não é dito explicitamente no texto, isso está anotado como "não especificado (presumivelmente GET)" — INFERIDO a partir da convenção geral do README raiz (GET=lista, POST=criação, PUT=atualização, DELETE=remoção) combinada com o padrão de endpoint documentado ali.

## Observações metodológicas

- Vários READMEs afirmam "controle total" (CRUD completo) da entidade mas só exibem o exemplo de listagem/consulta — nesses casos o inventário marca os demais métodos como NÃO VERIFICADO nesta pastas específica, mesmo que o padrão geral do repositório (documentado no README raiz) sugira que existam.
- Vários exemplos JSON publicados têm erros de sintaxe (vírgulas faltando/sobrando) — isso foi preservado como observação, não corrigido silenciosamente.
- Content-Type e header `Access-Token` seguem o padrão geral (ver `autenticacao.md`), exceto RD Station, que documenta autenticação via `api_token` na query string.
